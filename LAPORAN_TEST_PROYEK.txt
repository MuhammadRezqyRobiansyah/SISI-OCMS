2. TEMUAN KEAMANAN (PRIORITAS TINGGI)
--------------------------------------
[S-1] ChecksheetController@saveAnswer — TANPA cek role.
      Semua user login (termasuk Management, atau user baru tanpa role) bisa
      mengubah jawaban checksheet via AJAX. Metode addItem/removeItem sudah
      dibatasi Mechanic/Supervisor/SuperAdmin, saveAnswer belum.
      Bonus bug: item_id tidak divalidasi terhadap template, sehingga
      jawaban dengan item_id ngawur ikut menaikkan progress (%).

[S-2] FabricationRequestController@edit & @update — TANPA cek role.
      Semua user login bisa mengubah isi dokumen FR (nomor, part, tanda
      tangan). Metode lain (scan/store/destroy) sudah dibatasi role.

[S-3] PartRequestController@updateStatus — TANPA cek role.
      Semua user login bisa mengubah status Part Request (open/ordered/
      received).

[S-4] Registrasi publik terbuka dan user baru TIDAK diberi role.
      Kombinasi dengan S-1..S-3: siapa pun bisa mendaftar sendiri lalu
      mengubah data checksheet/FR/PR. Saran: tutup route register (buat
      user hanya lewat admin), atau beri role default paling rendah dan
      tambahkan cek role di endpoint S-1..S-3.

Catatan tambahan (perilaku, bukan celah): membuka PDF FR otomatis mengubah
status FR menjadi "printed" — termasuk saat Management sekadar melihat.
Pertimbangkan hanya menandai printed untuk role pelaksana.


3. TEMUAN OPERASIONAL
----------------------
[O-1] QUEUE_CONNECTION=database tetapi tidak ada queue worker berjalan.
      Job duplikasi GSheet (DuplicateChecksheetGsheets) akan menumpuk di
      tabel jobs dan tidak pernah dieksekusi. Jalankan:
        php artisan queue:work
      atau ubah sementara ke QUEUE_CONNECTION=sync untuk demo.

[O-2] Symlink public/storage sebelumnya TIDAK ADA — sudah DIPERBAIKI
      (php artisan storage:link). Tanpa ini foto painting & sketsa FR
      tidak tampil.

[O-3] APP_DEBUG=true di .env. Wajib false jika dipakai di luar dev,
      karena stack trace bisa membocorkan konfigurasi.


4. PERFORMA & KUALITAS KODE (PRIORITAS MENENGAH)
-------------------------------------------------
[P-1] FabricationRequestService::scanCandidates — pencocokan kandidat
      terhadap FR existing dilakukan nested loop O(N^2). Aman untuk
      puluhan part, akan lambat jika ratusan part per komponen.

[P-2] FabricationRequestService::nextNumber — pengambilan nomor urut FR
      tidak dibungkus lock/transaction; dua request bersamaan bisa dapat
      nomor FR sama (race condition, terutama SQLite). Saran: bungkus
      dengan DB::transaction + lockForUpdate, atau tabel counter khusus.

[P-3] show.blade.php makin besar (semua panel stage dalam satu file).
      Berfungsi baik, tapi pertimbangkan pecah per-stage ke partial
      (@include) agar mudah dirawat.

[P-4] Embed GSheet stage 2/4/5 memakai trik offset iframe (top:-25px,
      left:-46px) untuk menyembunyikan toolbar — rapuh jika Google
      mengubah layout. Tidak perlu diubah sekarang, cukup diketahui.
